# Практическое руководство: post-training научных ответов

Этот проект — небольшое контролируемое исследование на синтетических задачах.
Это публичная демонстрация подхода для конфиденциальных консалтинговых проектов.
Клиентские данные и результаты здесь не представлены. Фактические результаты
находятся в `reports/research_report.md` и `experiments/`; не заменяйте их ожиданиями.

## 1. Pretraining и исходная модель

При autoregressive pretraining модель минимизирует отрицательное логарифмическое
правдоподобие следующего токена:

    L_pretrain(θ) = − E_x Σ_t log π_θ(x_t | x_<t).

Градиенты изменяют параметры сети, чтобы предсказывать продолжения текста.
Это не оптимизация истинности научных утверждений: ошибочное предложение тоже
может быть правдоподобным продолжением. В нашем эксперименте исходная
Qwen2.5-0.5B-Instruct уже прошла instruction tuning. Мы не воспроизводим её
pretraining и не сравниваем с raw base checkpoint. Добавляем узкое post-training.

## 2. SFT: условное правдоподобие правильного ответа

    L_SFT(θ) = − E_(x,y) Σ_t log π_θ(y_t | x, y_<t).

`src/scireason/training.py`, ветка SFTTrainer, использует prompt/completion.
Chat template вставляет system/user/assistant delimiters; tokenizer превращает
строку в индексы. `completion_only_loss=True` исключает prompt из loss:
его labels равны −100. Prompt остаётся в attention context и влияет на ответ.
Padding также не должен вносить вклад в loss. Тест интеграции проверяет маску,
обновление адаптеров и неизменность замороженных весов.

Teacher forcing подаёт настоящие предыдущие токены ответа. При inference модель
видит уже собственные токены, поэтому низкий training loss не гарантирует правильных
свободных генераций. Кроме того, снижение loss может отражать усвоение JSON-формата.
Validation loss считается на другой формулировке знакомых операций; test включает
также новые семейства. Нельзя выбирать параметры по test и затем называть его независимым.

## 3. LoRA и вычисления

Для выбранной линейной матрицы W используется:

    W_eff = W_frozen + (α/r) B A.

Здесь r=8, α=16, адаптеры добавлены в q_proj и v_proj attention. Базовые веса
заморожены. SFT/DPO обновляют A и B; reward model также обновляет scalar score head.
Малое число обучаемых параметров экономит optimizer state, но backpropagation всё
равно проходит через сеть, и activations требуют памяти. Это LoRA в float32,
не QLoRA: bitsandbytes/CUDA здесь не используются. На M4 Pro работает PyTorch MPS.
Эффективный batch=8 получается накоплением градиентов восьми microbatch по одному.

## 4. DPO: относительное предпочтение с reference policy

Для общего prompt x и ответов y+ и y−:

    Δθ = log πθ(y+|x) − log πθ(y−|x)
    Δref = log πref(y+|x) − log πref(y−|x)
    L_DPO = −log σ[β(Δθ − Δref)].

Логарифмы последовательностей — суммы по completion-токенам, не prompt. DPO учится
увеличивать относительное правдоподобие chosen по сравнению с rejected относительно
фиксированного reference. Это не отдельный reward model и не rollout-based RL.
Reference задаёт точку отсчёта и связан с KL-регуляризованной постановкой, из которой
выведен DPO. Но минимизация конечного DPO loss сама по себе не гарантирует малую
измеренную KL на всех запросах.

В коде загружается SFT adapter с `is_trainable=True`. Проверенная версия TRL создаёт
копию `ref`; перед обучением код проверяет равенство параметров и отсутствие градиентов
у reference. Отключение SFT adapter дало бы исходную Qwen и было бы другим экспериментом.
`precompute_ref_log_probs` кеширует константы reference. Beta=.1; контролируемый запуск
при .5 меняет только beta. Нельзя интерпретировать beta просто как learning rate.

DPO может уменьшать probability обоих ответов, увеличивая лишь их относительное
преимущество. Поэтому preference loss не заменяет генеративную оценку. Наши rejected
примитивны; модель может выучить их статистические особенности вместо корректности.

## 5. Reward model

Отдельная сеть возвращает одно число rφ(x,y). Bradley–Terry loss:

    L_RM = −log σ[rφ(x,y+) − rφ(x,y−)].

Дополнительно включён небольшой centering penalty с коэффициентом .01 в RewardTrainer.
Он контролирует произвольный сдвиг reward scores. Положительный margin означает,
что chosen получил больший reward. Ноль — ничья, в accuracy она считается ошибкой.
Градиенты обновляют LoRA и новую scalar head, а не языковой генераторный objective.
Абсолютные reward scores не являются вероятностью истинности.

`reward_evaluation.py` проверяет unseen пары и OOD families. Добавление одной и той же
риторической фразы к correct или incorrect ответу — контролируемая проверка поверхностной
чувствительности. Она одновременно нарушает JSON-схему; это смешение verbosity и format,
которое обязательно указано. Высокая pairwise accuracy на наших парах не доказывает
устойчивость к оптимизатору, активно ищущему способы обмануть reward.

## 6. PPO и отличие от DPO

В RLHF reward model обычно обучают по предпочтениям, затем используют для on-policy
rollouts. PPO обновляет policy по сгенерированным ответам. Reference policy заморожена;
old policy фиксирует вероятность при сборе batch; это разные роли.
Value model оценивает ожидаемую отдачу; advantage может вычисляться через GAE.
Clipped surrogate для importance ratio ρ_t=πθ(a_t|s_t)/π_old(a_t|s_t):

    L_clip = E[min(ρ_t A_t, clip(ρ_t,1−ε,1+ε) A_t)].

Максимизируют surrogate, обучают value head на returns, обычно добавляют штраф KL
к reference и иногда entropy bonus. Clipping ограничивает суррогатный стимул к большим
изменениям, но не является жёсткой гарантией trust region. Reward hacking — рост proxy
reward при ухудшении целевой полезности/истинности. DPO тоже может переобучаться на
прокси предпочтений, хотя отдельный reward model ему не нужен.
PPO в этом проекте не следует считать реализованным без отдельного выполненного run.
GRPO — другой алгоритм и не заменяет доказательство реализации PPO.

## 7. Как читать графики и метрики

Training loss — качество оптимизации на обучающих данных; validation loss — перенос
того же objective на validation. Разрыв может указывать на overfitting. Для DPO нельзя
сравнивать raw loss разных beta как одну шкалу научной корректности. Для RM важны
accuracy, распределение margin и конкретные ошибки, а не только средний reward.

Primary accuracy включает format errors. Numeric MAE только по parseable ответам может
выглядеть лучше, когда модель перестаёт отвечать на трудные задачи: смотрите coverage.
Abstention precision = правильные отказы / все отказы; recall = правильные отказы /
все задачи, требующие отказа. Неопределённый знаменатель обозначается null, не нулём.
Unsupported-assertion rate относится только к специально заданным claim tasks.

Paired bootstrap сохраняет соответствие задач между моделями. Его 95% interval
условен на текущих шаблонах и одном training seed. Он не включает систематическую
ошибку benchmark, загрязнение pretraining или variability обучения. 12 задач на
семейство дают очень грубую оценку; независимых семейств всего десять.

## 8. Самостоятельные упражнения

1. Baseline: откройте десять predictions, вручную разделите ошибки расчёта и формата.
2. SFT: объясните один batch labels и найдите первый supervised token; затем измерьте
   эффект отключения маски на отдельном эксперименте, не подменяя основной результат.
3. DPO: вычислите loss вручную для двух наборов log probabilities и beta .1/.5.
4. RM: придумайте incorrect ответ, которому reward назначает высокий score, и объясните,
   почему это контрпример к интерпретации reward как истинности.
5. Evaluation: создайте новый family вне существующих шаблонов и заморозьте его до обучения.
6. Reproduction: самостоятельно выполните CPU-тесты и загрузку одного adapter checkpoint.

Экспериментальные карточки с вопросом, процедурой, результатом и ограничениями
добавлены в research report; наблюдённые числа должны совпадать с JSON-артефактами.
